## 1. Подключение к брокеру

| Параметр     | Значение            |
|--------------|---------------------|
| Брокер       | `broker.emqx.io`    |
| Порт         | `1883` (TCP/MQTT)   |
| Протокол     | MQTT v3.1.1         |
| Авторизация  | не требуется        |
| Device ID    | `A0001` (по умолчанию) |

> **Важно:** `device_id` должен совпадать с идентификатором, прошитым в контроллере. При несовпадении устройство вернёт код ошибки `-3`.

## 2. Структура топиков

```
/Gomel/Tar/
├── sensors/    ← устройство публикует данные с датчиков (подписаться)
└── modules/    ← клиент отправляет команды управления (публиковать)
```

| Топик                  | Направление        | Описание                                     |
|------------------------|--------------------|----------------------------------------------|
| `/Gomel/Tar/sensors/`  | Устройство → клиент | Телеметрия датчиков, раз в ~30 секунд       |
| `/Gomel/Tar/modules/`  | Клиент → устройство | Команды управления модулями и расписанием   |

---

## 3. Входящие сообщения — данные с датчиков

Устройство периодически публикует JSON в топик **`/Gomel/Tar/sensors/`**.

### Формат

```json
{
    "device_id": "A0001",
    "data": [
        { "SensorId": 1, "Type": "airTemperature",  "Value": 24.38, "Unit": "C"  },
        { "SensorId": 2, "Type": "airHumidity",      "Value": 29.21, "Unit": "%"  },
        { "SensorId": 3, "Type": "pressure",          "Value": 100761.875, "Unit": "Pa" },
        { "SensorId": 4, "Type": "plantHeight",       "Value": 39.76, "Unit": "cm" },
        { "SensorId": 5, "Type": "light",             "Value": 52.82, "Unit": "%"  },
        { "SensorId": 6, "Type": "soilTemperature",  "Value": 28.12, "Unit": "C"  },
        { "SensorId": 7, "Type": "soilMoisture",     "Value": 100.0, "Unit": "%"  }
    ]
}
```

### Поля

| Поле        | Тип    | Описание                             |
|-------------|--------|--------------------------------------|
| `device_id` | string | Идентификатор устройства             |
| `data`      | array  | Массив объектов показаний датчиков   |
| `SensorId`  | int    | Порядковый номер датчика (1–7)       |
| `Type`      | string | Тип датчика (см. [раздел 6](#6-типы-датчиков)) |
| `Value`     | float  | Числовое значение показания          |
| `Unit`      | string | Единица измерения                    |

## 4. Исходящие сообщения — управление модулями

Все команды отправляются в топик **`/Gomel/Tar/modules/`** в формате JSON.

### Базовая структура команды

```json
{
    "device_id":  "A0001",
    "message_id": "01JKY5E122HBQSZKXMF0F7HR44",
    "mode":       "1",
    "action":     "none",
    "type":       "dayLight",
    "schedule_unit": {
        "kind":             "",
        "schedule_unit_id": "",
        "interval":         {},
        "quantity":         {}
    }
}
```

### Поля команды

| Поле            | Тип    | Обязательно | Описание                                                   |
|-----------------|--------|-------------|------------------------------------------------------------|
| `device_id`     | string | да          | Идентификатор устройства                                  |
| `message_id`    | string | да          | Уникальный ID сообщения в формате [ULID](https://github.com/ulid/spec) |
| `mode`          | string | да          | Режим работы модуля: `"0"`, `"1"`, `"2"`, или `"-1"` (не менять) |
| `action`        | string | да          | Действие над расписанием: `"none"`, `"add"`, `"delete"`   |
| `type`          | string | да          | Тип модуля (см. [раздел 5](#5-типы-модулей))              |
| `schedule_unit` | object | да          | Объект единицы расписания (пустой при `action: "none"`)   |

---

### 4.1 Изменение режима работы

Используется, когда нужно только переключить режим, **не трогая расписание**.

- `mode` = `"0"` / `"1"` / `"2"` — нужный режим
- `action` = `"none"` — не изменять расписание
- `schedule_unit` — передаётся с пустыми полями

```json
{
    "device_id":  "A0001",
    "message_id": "01JKY5E122HBQSZKXMF0F7HR44",
    "mode":       "1",
    "action":     "none",
    "type":       "dayLight",
    "schedule_unit": {
        "kind":             "",
        "schedule_unit_id": "",
        "interval":         {},
        "quantity":         {}
    }
}
```

---

### 4.2 Управление расписанием

Используется, когда нужно добавить или удалить единицу расписания, **не меняя текущий режим**.

- `mode` = `"-1"` — режим не менять
- `action` = `"add"` или `"delete"`
- `schedule_unit` — заполненный объект с данными единицы

**Добавление единицы:**

```json
{
    "device_id":  "A0001",
    "message_id": "01JKY5E122HBQSZKXMF0F7HR44",
    "mode":       "-1",
    "action":     "add",
    "type":       "dayLight",
    "schedule_unit": {
        "kind":             "power",
        "schedule_unit_id": "01JKY5E122ASDF098080ASD8",
        "interval": {
            "start": "01T00:00",
            "end":   "07T23:59"
        },
        "quantity": {
            "magnitude": 50,
            "unit":      "%"
        }
    }
}
```

**Удаление единицы:**

```json
{
    "device_id":  "A0001",
    "message_id": "01JKY5E122HBQSZKXMF0F7HR44",
    "mode":       "-1",
    "action":     "delete",
    "type":       "watering",
    "schedule_unit": {
        "kind":             "power",
        "schedule_unit_id": "01JKY5E122ASDF098080ASD8",
        "interval": {
            "start": "01T00:00",
            "end":   "02T23:10"
        },
        "quantity": {
            "magnitude": 50,
            "unit":      "%"
        }
    }
}
```

> **Важно:** При удалении необходимо передавать **все поля** `schedule_unit` (включая `interval` и `quantity`), а не только `schedule_unit_id`.

## 5. Типы модулей

Поле `"type"` в команде определяет, каким модулем управляет сообщение.

| Значение `type` | Описание                     |
|-----------------|------------------------------|
| `"dayLight"`    | Лампы дневного освещения     |
| `"uvLight"`     | УФ-лампы                     |
| `"watering"`    | Система полива               |
| `"heater"`      | Нагреватель                  |
| `"humidifier"`  | Увлажнитель воздуха          |
| `"fan"`         | Вентилятор                   |
| `"waterPump"`   | Насос                        |
| `"airFlap"`     | Вентиляционная заслонка (серво) |

---

## 6. Типы датчиков

| Значение `Type`    | Описание                | Единица |
|--------------------|-------------------------|---------|
| `airTemperature`   | Температура воздуха     | `C`     |
| `airHumidity`      | Влажность воздуха       | `%`     |
| `pressure`         | Атмосферное давление    | `Pa`    |
| `plantHeight`      | Высота растения         | `cm`    |
| `light`            | Уровень освещённости    | `%`     |
| `soilTemperature`  | Температура почвы       | `C`     |
| `soilMoisture`     | Влажность почвы         | `%`     |

---

## 7. Режимы работы

| Значение `mode` | Название | Описание                                                                 |
|-----------------|----------|--------------------------------------------------------------------------|
| `"0"`           | ВЫКЛ     | Модуль выключен (0% мощности)                                           |
| `"1"`           | ВКЛ      | Модуль включён на полную мощность (100%), расписание игнорируется       |
| `"2"`           | АВТО     | Устройство управляет модулем по расписанию (значения из `schedule_unit`) |
| `"-1"`          | —        | Служебное значение: **не изменять** текущий режим (используется при управлении расписанием) |

## 8. Объект `schedule_unit`

Описывает одну временну́ю запись в расписании модуля.

```json
{
    "kind":             "power",
    "schedule_unit_id": "01JKY5E122ASDF098080ASD8",
    "interval": {
        "start": "01T00:00",
        "end":   "07T23:59"
    },
    "quantity": {
        "magnitude": 75,
        "unit":      "%"
    }
}
```

### Поля `schedule_unit`

| Поле               | Тип    | Описание                                              |
|--------------------|--------|-------------------------------------------------------|
| `kind`             | string | Тип управляющего параметра: `"power"` или `"time"`    |
| `schedule_unit_id` | string | Уникальный ID записи в формате ULID                  |
| `interval`         | object | Временной интервал действия записи                   |
| `interval.start`   | string | Начало интервала: `"DDThh:mm"` (день и время)        |
| `interval.end`     | string | Конец интервала: `"DDThh:mm"` (день и время)         |
| `quantity`         | object | Целевое значение (мощность, уровень и т.д.)          |
| `quantity.magnitude` | int  | Числовое значение (например, `50`)                   |
| `quantity.unit`    | string | Единица значения (`"%"`, `"W"`, `"lux"` и др.)       |

### Формат поля `interval`

```
"DDThh:mm"
 │  │ └── минуты (00–59)
 │  └──── часы   (00–23)
 └─────── день   (01–07 для дней недели, или порядковый номер дня цикла)
```

**Примеры интервалов:**

| `start`     | `end`       | Смысл                                     |
|-------------|-------------|-------------------------------------------|
| `"01T06:00"` | `"01T22:00"` | Каждый день с 06:00 до 22:00            |
| `"01T00:00"` | `"07T23:59"` | Весь цикл с первого по седьмой день     |
| `"02T08:00"` | `"02T20:00"` | Второй день цикла с 08:00 до 20:00      |

## 9. Коды ответов устройства

После обработки команды устройство **не публикует явный ответ** в отдельный топик — обратная связь реализована внутри прошивки. Тем не менее, в логике устройства определены следующие коды:

| Код  | Значение                                      |
|------|-----------------------------------------------|
| `2`  | Успешно: изменение расписания применено       |
| `1`  | Успешно: режим изменён                        |
| `-1` | Ошибка: не удалось изменить режим             |
| `-2` | Ошибка: не удалось применить изменение расписания |
| `-3` | Ошибка: `device_id` не совпадает             |
| `-4` | Ошибка: не удалось разобрать JSON             |

---

## 10. Правила составления сообщений

1. **Нельзя** совмещать изменение режима (`mode ≠ "-1"`) и манипуляцию с расписанием (`action ≠ "none"`) в одном сообщении. Это два отдельных запроса.

   ```
   ❌ Неправильно:
   { "mode": "2", "action": "add", ... }

   ✅ Правильно — сначала:
   { "mode": "2",  "action": "none", ... }

   ✅ Потом отдельно:
   { "mode": "-1", "action": "add",  ... }
   ```

2. Поле `message_id` должно быть уникальным для каждого сообщения. Рекомендуется использовать формат [ULID](https://github.com/ulid/spec) (26 символов из алфавита `0-9A-Z` без `I`, `L`, `O`, `U`).

3. При `action: "none"` объект `schedule_unit` должен присутствовать, но с **пустыми** значениями:
   ```json
   "schedule_unit": { "kind": "", "schedule_unit_id": "", "interval": {}, "quantity": {} }
   ```

4. Порядок полей в JSON не важен — устройство использует десериализацию по ключам.

## Запуск GUI-клиента

```bash
pip install -r requirements.txt
python3 smartgrowhub.py
```

GUI автоматически подключается к брокеру, подписывается на топик датчиков и позволяет управлять всеми модулями через графический интерфейс.
